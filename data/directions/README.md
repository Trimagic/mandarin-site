# Данные страниц направлений

`types.ts` — общий контракт шаблона; `phones.ts` — первая страница; `index.ts` — реестр и поиск по slug. Данные сериализуемые, без JSX, компонентов и функций внутри объектов.

Источник URL и услуг: `концепт/content/site-pages.md`. Для нового направления создайте объект `DirectionPageData` и добавьте его в `directionPages`.

Будущий шаблон выводит блоки в порядке: hero → services → problems → devices → conditions → process → works → reviews → faq → contact. Заголовок H1 складывается из `hero.title` и `hero.accent`. Каталогу услуг назначается `id="services"`. Общие контакты, шапка и футер остаются общими компонентами сайта.

Изображение техники и адаптивные фоны заданы отдельно для наложения кодом. Широкий фон с клетчатой подложкой не используется. Иконки и оформление выбирает шаблон, а не контент.

Цены структурированы: `from`, `by-model`, `after-diagnosis`. Для `from` показывать «от {amount} BYN» и учитывать `note`, особенно для чистки после воды. `pricesVerified: false` означает, что цены ещё не сверены с мастерской.

Пустые `works.items` и `reviews.items` нужно скрывать: не подставлять вымышленные отзывы или выдавать сгенерированные фотографии за выполненные работы.

Дочерние URL формируются через `getDirectionItemHref`. Они описывают планируемые страницы; до реализации маршрутов шаблон не должен выводить ведущие на 404 ссылки. Этот слой данных сам маршруты не создаёт.
